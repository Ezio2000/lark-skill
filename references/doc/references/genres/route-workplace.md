# Genre Router: Workplace (`router.workplace`)

Intra-organizational decision-making, execution, and record-keeping go through this category; first select by reader task and lifecycle and read only one leaf; keywords are used only for recall, and exclusion signals take precedence over synonymous terms.

| Reader task / keywords, strong signals, and exclusions | Leaf |
|-|-|
| Quick awareness, brief judgment, or pre-meeting preparation; memos, decision summaries, pre-meeting materials. Full approval justification goes to Proposal; periodic status goes to Weekly | [`memo-brief.md`](memo-brief.md) |
| Judging status, deviations, risks, and next steps relative to commitments on a periodic basis; weekly reports, daily reports, monthly reports, project status. Cause learning goes to Retrospective; full analysis goes to Report | [`weekly-report.md`](weekly-report.md) |
| Requesting a named decision-maker to approve direction, budget, resources, or execution commitments; proposals, project initiation, resource requests. Settled product behavior goes to PRD | [`proposal.md`](proposal.md) |
| Turning a one-time project, change, special initiative, or marketing campaign with a settled direction into deliverables, dependencies, milestones, and acceptance that can be advanced collaboratively; project plans, execution plans, implementation plans. Still comparing directions or requesting approval goes to Proposal / Report; repeated stable paths go to SOP | [`execution-plan.md`](execution-plan.md) |
| Writing authorized internal rules / arrangements, reviewable inspection and rectification records, or an approved organizational position into a formal vehicle; policies, company notices, rectification records, speech drafts. Direction pending approval goes to Proposal; complex execution goes to Execution Plan; statutory official documents go to Official; `正式` alone does not trigger | [`formal-doc.md`](formal-doc.md) |
| Drafting, reviewing, or issuing statutory official documents of Party and government organs; explicitly requires official document / red-header / red-seal / formal issuance, or statutory document types appear together with issuing elements such as organ correspondence relationships, document numbers, and primary recipients. `通知 / 报告 / 公告 / 纪要 / 正式 / 官方` alone does not trigger | [`official-redhead.md`](official-redhead.md) |
| Recording the decisions, objections, actions, and approval status of a meeting that has already occurred; meeting minutes, action items. Verbatim transcripts do not go through this leaf; statutory official document minutes go to Official | [`meeting-minutes.md`](meeting-minutes.md) |
| Extracting evidence-based learning from a completed cycle / event and changing the next round; retrospectives, reviews, lessons learned. Current status goes to Weekly; active unknown incidents go to Technical | [`retrospective.md`](retrospective.md) |
| With direction settled, defining user problems, scope, product behavior, and acceptance; PRDs, user stories, acceptance criteria. Whether to invest goes to Proposal; implementation trade-offs go to Technical | [`prd.md`](prd.md) |
| Reviewing future technical designs, querying precise contracts, or investigating unknown failures; RFCs, APIs, architecture, incident investigations. Product behavior goes to PRD; settled repeated paths go to SOP | [`technical-doc.md`](technical-doc.md) |
| Repeatedly reaching a final state via an approved, verifiable path, or presetting response paths for known event categories; SOPs, runbooks, duty / operations manuals, BCP / response plans. If an emergency plan mainly publishes authoritative responsibilities, it goes to Formal; statutory issuance goes to Official; active unknown incidents go to Technical; a one-time learning tutorial goes to Knowledge | [`sop-tutorial.md`](sop-tutorial.md) |
