# mail templates


Mail templates refer to the Feishu OAPI personal mail template system ("My Templates" in the user's mailbox), which can be managed in the Feishu client. It is different from the static HTML template library under the repository [`../assets/templates/`](../assets/templates/); static HTML templates are merely local material that can be copied for reference when writing a single email.

<a id="何时使用"></a>
## When to use

- Create / update a long-term reusable email framework: use `+template-create` / `+template-update`.
- Send mail using an existing template: pass `--template-id <id>` in `+send` / `+draft-create` / `+reply` / `+reply-all` / `+forward`.
- List / get / delete personal templates: use the native API `user_mailbox.templates {list|get|delete}`.

<a id="管理模板"></a>
## Managing templates

- [`+template-create`](lark-mail-template-create.md) — Create a new template. `--name` is required; the body is provided via either `--template-content` or `--template-content-file` (choose one); supports automatic upload of HTML inline images to Drive.
- [`+template-update`](lark-mail-template-update.md) — Full-replacement update (**the backend has no optimistic locking, last-write-wins**). Supports `--inspect` (read-only projection) / `--print-patch-template` (patch skeleton) / `--patch-file` (structured patch) / flat `--set-*` flag.

<a id="套用模板"></a>
## Applying templates

`+send` / `+draft-create` / `+reply` / `+reply-all` / `+forward` all support `--template-id <id>`. `--template-id` must be a **decimal integer string**.

<a id="创建模板后立即发信-checklist"></a>
### Checklist for sending mail immediately after creating a template

1. `+template-create --as user --name <name> --subject <subject> --template-content <html>`, capture the real `template_id`.
2. When the user asks to send, do not stop at the template or draft: `+send --as user --to <email> --template-id <template_id> --confirm-send`; only pass `--subject` when the template subject needs to be overridden.
3. After returning `message_id`, call `user_mailbox.messages send_status` to report the delivery status.

<a id="合并规则"></a>
## Merge rules

| # | Scenario | Merge strategy |
|---|------|----------|
| Q1 to/cc/bcc | All 5 shortcuts | The user's `--to/--cc/--bcc` first overrides the draft's original values, then is **appended without deduplication** to the template's tos/ccs/bccs |
| Q2 subject | `+send` / `+draft-create` | User `--subject` > draft subject > template subject |
|  | `+reply` / `+reply-all` / `+forward` | User `--subject` overrides the automatic Re:/Fw:; otherwise keep Re:/Fw: + the original email subject. **The template subject is ignored** (to preserve the conversation thread) |
| Q3 body | `+send` / `+draft-create` | Empty draft body → use the template; non-empty HTML → `draftBody + <br><br> + tplContent`; non-empty plain-text → `\n\n` concatenation |
|  | `+reply` / `+reply-all` / `+forward` | Template content is injected before `<blockquote>`; if there is no blockquote, append; plain-text templates go through emlbuilder plain-text append |
| Q4 attachments | All 5 shortcuts | Template inline (SMALL) attachments are downloaded by the CLI via `user_mailbox.template.attachments.download_url` and then injected as MIME parts; SMALL non-inline attachments are injected the same way; LARGE (`attachment_type=2`) attachments are not downloaded, and only `file_key` is placed in the `X-Lms-Large-Attachment-Ids` header to let the server render the download card |
| Q5 cid conflict | inline images | cid is generated by UUID v4 (collision probability ~ 2^-122), with no explicit detection |

**Warning**: When `+reply` / `+reply-all` + a template and the template has its own tos/ccs/bccs, the CLI prints to stderr: `warning: template to/cc/bcc are appended without de-duplication; you may see repeated recipients. Use --to/--cc/--bcc to override, or run +template-update to clear template addresses.`

<a id="size-约束"></a>
## Size constraints

- A single template `template_content` <= 3 MB.
- `body + inline + SMALL` cumulative <= 25 MB.
- After exceeding 25 MB, the remaining non-inline attachments in that batch switch to LARGE; inline attachments cannot switch.

<a id="原生-api"></a>
## Native API

```bash
lark-cli mail user_mailbox.templates list --params '{"user_mailbox_id":"me"}'
lark-cli mail user_mailbox.templates get --params '{"user_mailbox_id":"me","template_id":"<id>"}'
lark-cli mail user_mailbox.templates delete --params '{"user_mailbox_id":"me","template_id":"<id>"}'
```
